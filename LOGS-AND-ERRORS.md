# Логи и ошибки саун — 26 сентября 2026

Реализация одинакова в малой и большой сауне. Проверка локальная, с подменённым сервером данных. На установки эта сборка не загружалась и не запускалась.

## Что проверять в интерфейсе

Войти администратором. Во вкладке «Ошибки» сверху показаны текущие флаги контроллера и счётчики, ниже — история событий. «Логи» содержит все уровни событий контроллера и сохраняет существующий журнал действий и показаний.

- Уровни: 0 — информация, 1 — предупреждение, 2 — сбой, 3 — авария, 4 — крах, 5 — технический лог. Неизвестный уровень показывается отдельно и не скрывается в фильтре проблем.
- Доступны период от 15 минут до 90 дней (включая 30 и 90 дней), уровень, источник, поиск, подробности и выгрузка выбранных записей в JSON.
- Журнал сервера может содержать несколько устройств. Источник показан у каждой записи; его можно отфильтровать. Автоматическая привязка числового logUnit к имени HomePLC не предполагается.
- При потере связи выводится предупреждение. Последний успешный ответ сохраняется с отметкой времени. Ошибка запроса не заменяется пустым журналом.
- Текущие флаги и история читаются независимо. Запись в истории не означает, что ошибка активна сейчас. Отсутствующие регистры обозначены «—».
- Просмотр обновляется каждые 15 секунд. Чтение журнала и диагностики не пишет команды в контроллер.

## Основание и ограничения протокола

Источники: «Стратегии и алгоритмы.pdf», страницы 13–17; лист Air2 в Air2Common.xls.

Уровень события не меняется из-за снижения защиты. Фактическая реакция контроллера — отдельное поле. Для EventPLC числовые value и prevValue показаны как исходные коды реакции и источника: таблица соответствия этих кодов в предоставленных материалах отсутствует. Не делаем вывод «остановлен/перезапущен» только по уровню ошибки. Отменённый Service2 не используется.

Текущие регистры:

| Регистр | Назначение |
| --- | --- |
| 0x0301 | State: биты 8–11 — сбой, авария, замерзание, крах |
| 0x0305 | WorkState: биты 6, 7, 8, 14, 15 — замерзание, сбой, авария, Modbus, крах |
| 0x0600 | ModbusErrors |
| 0x0604 | ErrRestarts |
| 0x0605 | FailRestarts |

0x8000 является допустимым WorkState с установленным битом краха, а не признаком отсутствия данных. Управление уровнем защиты и сброс ошибок не добавлены. Подтверждение/завершение отдельной аварии нельзя достоверно определить по endTime: старый API может заполнять его временем создания события.

Запрос журнала остаётся POST /api/ess2/events/list с lastminutes и типами [16, 3, 4, 6]. Это типы записей, не уровни ошибок. Клиент сохраняет повторную авторизацию при 401/403. Отсутствующие поля ответа остаются пустыми; идентификатор события передаётся строкой без потери точности.

## Запуск малой сауны для проверки в 301

Имя юнита теперь задаётся ключом `--modbus.api.log-name=HomePLC`. Он применяется к чтению и записи контроллера. Без ключа остаётся прежнее имя Sauna7000PLC.

Если JAR запускается на том же компьютере, что сервер данных 301, и там запущен сервер на **4569**, пример:

```sh
java -jar sauna.jar --modbus.api.ip=127.0.0.1 --modbus.api.port=4569 --modbus.api.log-name=HomePLC --server.port=8082
```

Если JAR запускается на Mac через VPN до 301:

```sh
java -jar sauna.jar --modbus.api.ip=172.16.6.119 --modbus.api.port=4569 --modbus.api.log-name=HomePLC --server.port=8082
```

`modbus.api.port` — фактический порт запущенного сервера данных (например, для 4571.bat указать 4571). `server.port` — свободный порт веб-интерфейса. Указанные 4569 и 8082 — пример, а не результат проверки доступности.

Запускать из каталога с нужной базой пользователей. Обновление JAR само по себе не меняет параметры службы/команду запуска: HomePLC нужно указать в ней. Для существующих саун сохранить их собственные параметры запуска.

## Проверки

В каждом проекте отдельно: 46 фронтенд-тестов и 86 серверных тестов, включая интеграционные HTTP-тесты с локальным имитатором API. Проверены уровни, неизвестные коды, пропущенные поля, точность ID, регистры, запрет доступа без роли администратора, 401 с повторной авторизацией, пустой ответ, 502/503 и настройка HomePLC.

Проверка в браузере с полностью подменённым API: фильтрация уровней, JSON-выгрузка, сохранение прежних записей при ошибке обновления, существующий журнал действий, экран компьютера и мобильная панель.

Реальное соответствие новой версии API Романова и поведение установки остаются для проверки через VPN. Локальные тесты этого не подтверждают.
