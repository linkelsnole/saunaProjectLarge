# Автоматические обновления большой сауны

## Автоматический переход открытой страницы

Каждая сборка получает уникальный `buildId`, одинаковый в JavaScript и `static/panel-build.json` внутри JAR. Публичный GET `/api/v1/platform-state` сообщает только ID запущенной сборки и признак установки, с `Cache-Control: no-store`.

Браузер проверяет состояние каждые 5 секунд, при возвращении на вкладку и взаимодействии. Во время установки показывает загрузку и проверяет каждые 2 секунды. После завершения перезагружает страницу; если установка откатилась, также возвращается к работающей версии. Сбой сети сам по себе не объявляется обновлением. Старая вкладка после сна сравнивает ID своей сборки с сервером.

Запросы интерфейса передают `X-Panel-Build`. Сервер отклоняет изменяющие запросы устаревшего интерфейса и запросы во время установки до вызова обработчика. Клиент не повторяет такие команды после перезагрузки. Уже принятые сервером команды это не отменяет. Несохранённый ввод при перезагрузке не переносится.

Для уже установленного загрузчика включить режим на сервере от его пользователя:

```bash
python3 tools/deployment/set_automatic.py --config /absolute/path/to/sauna-updater-APP/config.json
```

Скрипт проверяет существующую конфигурацию, берёт блокировку загрузчика и атомарно добавляет `automatic: true`. Он не создаёт новую службу и не запускает установку сам: её выполнит существующее минутное задание. До включения нужна первоначальная установка JAR с новым интерфейсом. Старая открытая вкладка ещё не содержит нового механизма — её один раз нужно перезагрузить.
